# F7: draft a SPEC from the curated SEE

The steward can request an Effort draft before publishing the first SPEC. The request binds the current SEE and freezes the available conversation at that point. The full curated SEE is included; unadopted comments are labeled evidence and bounded with explicit omission counts. If the governing text exceeds the configured input limit, drafting fails visibly rather than silently truncating it. Research is supplied with its existing status, including missing connections.

The draft uses the existing metering gateway, kill latch, daily allowance and shared spend caps. Only a matching draft job can request the larger output allowance. Provider output must validate as five bounded lists: requirements, success criteria, exclusions, assumptions and open questions. A stale or malformed response cannot publish a SPEC. The steward reviews the suggestion in an editable form and publishes it separately, with a source credit. No approval or build authority is inherited from the AI draft.

The fixture returns an explicitly synthetic draft. A configured real Effort provider receives the structured drafting instructions; no hosted model was called for verification. The existing first-reply and mention behavior remains available.

Decision packets now distinguish an unknown build price from an explicit operator-supplied zero. An unpriced plan no longer looks free.
